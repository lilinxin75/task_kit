# Task Kit — 项目级五段式任务工作系统

把 Spec Kit 的契约化开发思想迁移到管理任务：**宪法约束项目，契约约束任务**。先立项目宪法，再逐个 specify 任务；任务完成后复盘，把可复用规则晋升进宪法，然后 specify 下一个任务。

## 核心原则

1. **宪法先行**：项目下第一个动作是立宪法（CONSTITUTION.md），所有任务产物须过宪法校验，冲突即停。
2. **契约先行**：每个任务的产物是任务目录下的 markdown 文件，执行争议回到文件校验。
3. **强制对齐闸门**：阶段一（澄清）与阶段三（确认）是闸门，未经用户/决策人确认，不得进入重执行阶段。
4. **轻量对齐**：给决策人做选择题（A/B/C + 推荐项），一页纸、口头汇报 ≤15 分钟、结论前置 30 秒。
5. **沉没成本停机**：执行中发现关键假设被推翻或方向变化，立即停下回到阶段三，不硬推。
6. **经验晋升**：AAR 产出的项目级规则晋升进宪法（带来源任务），任务级规则留在任务目录。
7. **按返工成本裁剪**：不是所有任务都跑全流程，见下方裁剪表。

## 目录契约

位置：当前工作区根目录。项目级配置在 `.task-kit/`，任务工作产物 `tasks/`、素材库 `materials/`、共享输出 `outputs/` 在根目录可见（对齐 Spec Kit 的 `specs/` 模式）：

```
项目根/
├── .task-kit/               # 项目级：宪法、索引、脚本（隐藏目录）
│   ├── CONSTITUTION.md      # 项目宪法：版本号 + Sync Impact Report + 五节结构
│   ├── PROJECT.md           # 项目索引：任务清单、状态、跨任务依赖、Backlog
│   └── scripts/
│       └── task-new.sh      # 可选脚手架：自动分配编号建任务目录（无脚本时 task.new 手工按规则编号）
├── materials/               # 共享素材库：导入的素材整理归类后存放（跨任务复用）
├── outputs/                 # 共享输出：跨任务共享的产出
└── tasks/
    └── NNN-<任务slug>/      # 三位序号（001、002…），保证排序与跨会话定位
        ├── 00-STATE.md      # 任务状态卡：阶段/已完成产物/下一步/授权余量（模板 00-state.md）
        ├── 01-task.md       # 任务定义书（阶段一产出，模板 01-task.md）
        ├── 02-plan.md       # 方案骨架（阶段二产出，模板 02-plan.md）
        ├── 03-review.md     # 评审汇报稿与拍板记录（阶段三产出，模板 03-review.md）
        ├── 04-log.md        # 执行周志，追加式（阶段四产出）
        ├── 05-aar.md        # 复盘卡（阶段五产出）
        ├── 06-research.md   # 调研记录（阶段二按需产出，模板 06-research.md）
        ├── quickstart.md    # 快速上手（首个 task.new 生成，仅一次）
        ├── checklists/      # 质量门产物（task.check 落盘，CHKxxx 编号）
        ├── materials/       # 任务私有素材：中间产物、临时分析
        └── outputs/         # 任务默认输出：未指定地址的工作与输出落这里
```

**编号与扩展约定**：
1. `00-06` 编号为核心契约文件保留，不得挪作他用；任务特定产物从 `07` 起自由编号，或统一放 `materials/`。
2. 任务 slug 建议中文或小写英文加连字符，与编号用 `-` 连接（如 `tasks/001-rgbd技术调研/`）。
3. `checklists/`、`materials/`、`outputs/` 为约定子目录，按需创建，不强求每任务都有。

**落点决策规则**：
| 内容 | 落点 |
|---|---|
| 有 00–06 编号的契约产物 | 按契约落盘（tasks/NNN-slug/ 下对应文件），不得重定向到默认落点 |
| 素材导入 | 整理归类后落根级 `materials/` |
| 未明确指定保存地址的工作或输出 | 任务级 `tasks/NNN-slug/outputs/` |
| 跨任务共享的输出 | 根级 `outputs/` |
| 任务私有的中间产物与临时分析 | 任务级 `tasks/NNN-slug/materials/` |

同一素材/输出不得双处重复存放；跨处引用以相对路径标注来源。

每次写完任一产物文件后，必须同步更新该任务的 `00-STATE.md`；任务状态变化时同步更新 `PROJECT.md`。

## 通用行为契约（C1–C6）

每条阶段命令（constitution / new / clarify / plan / review / track / aar / done）MUST：

1. **C1 只做自身阶段**：完成自身产物落盘与闸门判定，不调用任何其他阶段命令。
2. **C2 停止**：到达停止点后停止，输出阶段完成报告。
3. **C3 报告三要素**：①本阶段产物清单（相对路径）②当前阶段与状态 ③下一建议命令 + 所需输入；缺一即为违约。
4. **C4 状态同步**：落盘产物后立即更新 00-STATE.md（frontmatter + 状态卡）与 PROJECT.md（状态变化时）。
5. **C5 授权检查**：进入下一阶段前检查 00-STATE 的 `chain_grants`；`=0` 时停止等待指令；`>0` 时可进入下一阶段并 -1（闸门处必停除外，见"授权语义"）。
6. **C6 宪法自查**：产物落盘前自查宪法红线，冲突点写入产物"宪法校验"行。

**停止点矩阵**：

| 命令 | 停止点 | 前置闸门 |
|---|---|---|
| task.constitution | 宪法落盘完成 | 无（修订须追加修订记录） |
| task.new | 任务目录 + 00-STATE 创建、PROJECT.md 登记完成 | 宪法未立时提示（用户明确跳过除外） |
| task.clarify | 01-task.md 落盘完成 | 澄清闸门：五要素齐备 + 复述确认 |
| task.plan | 02-plan.md（+ 06-research.md 按需）落盘完成 | 无显式闸门；深入沟通 = 分析展示 + 权衡讨论 |
| task.review | 03-review.md 落盘完成 | 评审闸门：A/B/C + 推荐 + 理由 + 风险 + 预案 + 三拍板 |
| task.track | 04-log.md 追加 + 周检项核对完成 | 建议先跑 task.check（非强制） |
| task.aar | 05-aar.md 完成 + 规则沉淀 | 无显式闸门 |
| task.done | PROJECT.md 状态更新完成 | 前置：05-aar 已完成；done 后询问下一任务（不执行 task.new） |

**阶段完成报告模板**（每次阶段停止时输出，缺一即违约）：

```
── 阶段完成报告 ──────────────────────────
① 本阶段产物：
   - <落盘文件相对路径清单>
② 当前状态：
   - 阶段：<stage> ｜ 状态：<进行中 / 闸门待批 / 已完成 / 挂起>
③ 下一步：
   - 建议命令：<next>（所需输入：<输入说明>）
   - 说"继续"推进一步；说"接下来连着跑"自动推进一段（闸门处仍会停）
──────────────────────────────────────────
```

**输出前自查**：报告三要素必须与 00-STATE.md frontmatter、磁盘实际落盘产物三方一致，方可输出。

## 命令（用户直接说，按语义识别，无需严格前缀）

| 指令 | 对应 Spec Kit | 动作 |
|---|---|---|
| `task.init <项目名>` | — | 建 `.task-kit/` 骨架 + 根目录 materials/、outputs/（不建 tasks/、不生成 quickstart.md），引导立宪法 |
| `task.constitution` | `/constitution` | 制定或修订项目宪法（套用 templates/00-constitution.md），修订须追加修订记录；落盘后停止 |
| `task.new <任务名>` | `/specify` | 分配下一个三位编号（根 tasks/ 下最大 NNN+1），建任务目录 + 00-STATE.md（模板 00-state.md），登记进 PROJECT.md；项目内无 quickstart.md 时在本任务目录生成一份（仅首个任务发生，模板 quickstart.md）；停在阶段一入口，不开始提问 |
| `task.clarify` | `/specify`+`/clarify` | 阶段一闸门：分析展示 + 提问（最多 2 轮 × 每轮 ≤6 问）→ 用户确认复述后写 01-task.md；落盘后停止 |
| `task.plan` | `/plan`+`/tasks` | 阶段二：基于 01 做分析展示与权衡讨论（议题树、假设、思路对比），不产正式方案；落盘 02-plan.md（+按需 06-research.md）后停止 |
| `task.review` | 规格评审 | 阶段三闸门：把 02 压缩成 SCQA + A/B/C 选择题汇报稿 → 三拍板 → 03-review.md 记录拍板/否决/待定；落盘后停止 |
| `task.track` | `/implement` | 阶段四：五段式周志追加到 04-log.md + 周检项核对；假设被推翻/方向变更触发回溯（见"回溯规则"）；完成后停止 |
| `task.check` | `/analyze`+`/checklist` | 宪法与一致性校验：①当前任务产物是否违反宪法红线/决策原则；②各产物间是否互相矛盾（01-task 目标 vs 02 计划 vs 03 拍板 vs 04 进度，06-research 存在时纳入）；输出 pass/fail 清单并落盘 `checklists/<校验类型>.md` |
| `task.aar` | `/converge` | 阶段五：四问复盘 → 05-aar.md；把项目级规则晋升进宪法（追加修订记录）；落盘后停止 |
| `task.done` | — | 关闭任务：确认 05-aar 完成 → PROJECT.md 状态改为已完成 → 主动询问下一个任务（询问不等于执行 task.new） |
| `task.list` | — | 列出项目所有任务（编号/任务名/当前阶段/状态，读 PROJECT.md） |
| `task.show` | — | 展示某任务当前状态卡：渲染 00-STATE.md frontmatter + 正文四栏，并做一致性自查（见下） |

**阶段命令停止行为**（C1/C2 落地）：每条阶段命令完成自身产物落盘与闸门判定后，到达停止点即停——输出"阶段完成报告"并等待用户指令；**禁止在用户未授权时自动调用下一阶段命令**。阶段推进只能由用户指令驱动：停止点处说"继续"（推进一步）或"接下来连着跑"（见"授权语义"）。

**task.show 一致性自查**：渲染状态卡前核对 `stages_done` 中每个 artifact 真实存在于磁盘、`stage` 与最新落盘产物一致；不一致时在输出中标注 ⚠️ 并给出差异清单。

## 闸门语义（Gate）

阶段一与阶段三是显式闸门，行为对齐 workflow gate step：

| 闸门 | 通过（approve） | 驳回（reject） |
|---|---|---|
| 阶段一 clarify | 复述获用户确认 → 落盘 01，放行阶段二 | 按反馈修订复述，再次确认；用户中止 → 任务暂停，00-STATE 记录挂起原因 |
| 阶段三 review | 决策人拍板 → 落盘 03，放行阶段四 | 方案被否 → 回阶段二修订；方向性推翻 → 回阶段一 |

未过闸门不得进入下一阶段；`task.track` 前建议跑 `task.check` 作执行期门禁。

### 授权语义（连跑授权）

授权存于 00-STATE.md frontmatter 的 `chain_grants`（整数，默认 0），跨会话持久。**闸门必停**：到达复述确认或三拍板时，即使 `chain_grants > 0` 也 MUST 强制停止等待拍板；闸门 approve（含闸门处说"继续"）不消耗授权。

| 用户话语 | 上下文 | 效果 |
|---|---|---|
| "继续" | 闸门处 | 闸门 approve，`chain_grants` 不变 |
| "继续" | 阶段停止点 | 推进一个阶段（+1 后立即消耗，净效果 = 前进一段） |
| "接下来连着跑" | 阶段停止点 | `chain_grants` += 1 |
| "连跑 N 个阶段" | 阶段停止点 | `chain_grants` += N |
| "无上限连跑" | 任意 | 拒绝（不支持开放式连跑），计数不变 |
| "回溯后继续" | 回溯触发点 | 回溯到达目标阶段后按一次授权推进 |
| "继续" | 非停止点/非闸门 | 不触发任何授权语义 |

**不变式**：
- I1：`chain_grants` ≥ 0
- I2：`chain_grants > 0` 时仍 MUST 在闸门处停止（闸门必停）
- I3：授权仅被"阶段推进"消耗，且跨会话持久（存于 00-STATE）

**C5 判定流程**：到达阶段停止点 → 读 `chain_grants` → `=0`：输出阶段完成报告并停止等待指令；`>0`：`chain_grants -= 1`，进入下一阶段（下一阶段自身闸门处仍必停）。

## 任务生命周期（项目内循环）

```
task.init → task.constitution
    └→ 循环：task.new → clarify → plan → review → track ─┬→ aar → done
                            ▲                            │
                            └──── 假设被推翻/方向变更 ────┘
    done 后 → task.new 下一个任务（继承宪法与 PROJECT.md 上下文）
```

### 回溯规则

触发：用户说"假设被推翻 / 方向变了 / 领导否了"（执行规则 7），无论当前在哪个阶段，立即停止当前动作，按下表确定目标阶段：

| 从 | 到 | 触发情形 |
|---|---|---|
| track | review | 假设被推翻 |
| track | clarify | 方向性推翻 |
| review | plan | 方案被否 |
| review | clarify | 方向性推翻 |
| plan | clarify | 前提缺失 |

**到达目标阶段即停**：在目标阶段入口输出阶段完成报告并等待用户指令，不自动重跑后续阶段。用户说"回溯后继续"按连跑授权 +1 处理（见"授权语义"）。

非法迁移：任何跳过闸门的顺向迁移（如 clarify 未复述确认 → plan）；未授权自动迁移。

## 阶段模板

生成产物时严格套用 `templates/` 下对应模板：

- `templates/00-constitution.md` — 项目宪法（版本号 + Sync Impact Report + Governance）
- `templates/00-project.md` — 项目索引
- `templates/00-state.md` — 任务状态卡（frontmatter 阶段/授权余量 + 状态卡四栏）
- `templates/01-task.md` — 任务定义书（五要素 + 澄清记录 + 复述确认）
- `templates/02-plan.md` — 方案骨架（议题树 / 打分表 / 假设清单 / 行动计划 / 分析记录）
- `templates/03-review.md` — 评审卡（SCQA + 选择题 + 会议结论 / 分析记录）
- `templates/04-log.md` — 执行周志（已完成/进行中/待解决/下一步/需要支持）
- `templates/05-aar.md` — AAR 复盘卡（四问 + 规则沉淀）
- `templates/06-research.md` — 调研记录（按需：Decision / Rationale / Alternatives / 证据来源）
- `templates/quickstart.md` — 快速上手（首个 task.new 生成到任务目录，仅一次）
- `templates/checklist.md` — 质量门清单（task.check 落盘用，CHKxxx 编号，reviewer-owned 语义）

## 裁剪规则（按"做错返工成本"判断）

| 任务类型 | 保留阶段 |
|---|---|
| 日常事务型（例行周报、常规审批） | 30 秒过五要素 → 直接执行，不落盘 |
| 临时协调型（跨部门拉通、临时会议） | 澄清 → 口头方案 → 确认 → 执行（只落盘 01） |
| 专项任务型（降本、上线、年度规划） | 全五段完整落盘 |
| 突发问题型（客诉、事故） | 5 分钟澄清 + 口头确认 → 执行 → 事后 task.aar |

宪法中"流程约束"一节可对以上默认值做项目级覆盖。

## 执行规则

1. **宪法规则**：宪法未立时，task.new 应先提示 task.constitution（用户明确跳过才允许）；每个阶段产物落盘前自查"是否违反宪法红线/决策原则"，冲突点写进产物文件的宪法校验行。宪法修订只能追加修订记录 + 文件头 Sync Impact Report，不改写历史条款；版本号遵守语义化——红线/原则语义变化 MAJOR，新增原则或扩展 MINOR，措辞澄清 PATCH。
2. **编号规则**：task.new 按项目根 `tasks/` 下现有最大 NNN + 1 分配三位编号；有 `scripts/task-new.sh` 时优先用脚本。旧项目无编号目录可直接沿用原名，不强制重命名。
3. **阶段一**深入沟通：先做分析展示再提问，最多提问 2 轮、每轮 ≤6 问，缺什么问什么；然后输出一段话复述请用户确认，确认（澄清闸门）后才写 01-task.md。禁止拿猜测当澄清。
4. **阶段二**议题树必须自查 MECE；80% 精力应压在前 20% 关键议题上；每个假设必须可证伪（写明"错了用什么事实验证"）。
5. **阶段三**必须输出"方案 A/B/C + 推荐项 + 理由 + 风险 + 预案"，禁止只抛问答题；结论区必须记录三件事：拍板了什么、否了什么、待定什么。
6. **阶段四**每次 track 前建议跑一次 task.check；每周检查：当前工作能否追溯到 02/03？假设有没有被推翻？有没有黄灯/红灯要提前预警？
7. **回溯触发**：用户说"方向变了 / 假设被推翻 / 领导否了"，无论当前在哪个阶段，按「任务生命周期·回溯规则」的回溯边表确定目标阶段重走确认；到达目标阶段即停。
