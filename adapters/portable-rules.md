# Task Kit 通用规则（适配任意 Agent：Cursor / ChatGPT / 其他）

> 用法：把本文件全文粘贴进目标 agent 的规则文件（如 Cursor 的 `.cursorrules` / `.cursor/rules/`、ChatGPT 的 Custom Instructions、其他 agent 的 system prompt 或项目记忆文件）。若目标 agent 支持文件读取，把 `core/` 目录一并放入可读路径，规则中的模板路径指向它即可。
> 版本：v2.0.0（目录契约破坏性变更，旧项目迁移见 core 所在包的 README）

# 管理任务五段式工作系统（task-kit）

先立项目宪法，再逐个 specify 任务；任务完成后复盘，把可复用规则晋升进宪法，然后 specify 下一个任务。**每条阶段命令完成自身产物后停止，输出阶段完成报告，等用户指令再推进。**

## 目录契约
在当前项目根下维护（v2.0.0 起 `tasks/` 上移至根目录，对齐 Spec Kit 的 specs/ 模式）：
```
项目根/
├── .task-kit/             # 项目级：宪法、索引、脚本
│   ├── CONSTITUTION.md    # 项目宪法：版本号+Sync Impact Report/使命/决策原则/红线/经验升级区/Governance
│   ├── PROJECT.md         # 项目索引：任务清单、状态、跨任务依赖、Backlog
│   └── scripts/task-new.sh
├── materials/             # 共享素材库：导入的素材整理归类后存放（跨任务复用）
├── outputs/               # 共享输出：跨任务共享的产出
└── tasks/<NNN-slug>/      # 三位序号（001、002…）+ 短 slug
    ├── 00-STATE.md        # 任务状态卡：阶段/已完成产物/下一步/连跑授权余量/更新时间
    ├── 01-task.md         # 任务定义书（v2.0.0 由 01-problem.md 更名）
    ├── 02-plan.md         # 方案骨架（含"分析记录/沟通过程"字段）
    ├── 03-review.md       # 评审卡（含"分析记录/沟通过程"字段）
    ├── 04-log.md          # 执行周志（追加式）
    ├── 05-aar.md          # 复盘卡
    ├── 06-research.md     # 调研记录（按需）
    ├── quickstart.md      # 快速上手（首个 task.new 生成，仅一次）
    ├── checklists/        # 质量门清单（task.check 落盘，CHKxxx 编号）
    ├── materials/         # 任务私有素材：中间产物、临时分析
    └── outputs/           # 任务默认输出：未指定地址的工作与输出落这里
```
落点规则：有 00–06 编号的契约产物按契约落盘；素材导入→根级 materials/；未指定地址的输出→任务级 outputs/；跨任务共享输出→根级 outputs/；任务私有中间产物→任务级 materials/。同一素材/输出不双处存放，跨处引用以相对路径标注来源。

每次写完产物同步更新 00-STATE.md；任务状态变化同步 PROJECT.md。

## 命令（用户说人话，按语义识别）
- **task.init <项目名>**：建 `.task-kit/` 骨架 + 根目录 materials/、outputs/，引导立宪法
- **task.new <任务名>**：分配下一个三位编号（根 tasks/ 最大 NNN+1），建任务目录（00-STATE 初始 chain_grants=0），登记 PROJECT.md；项目内无 quickstart.md 时在本任务目录生成一份（仅首个任务），停在阶段一入口，不开始提问
- **task.constitution**：制定/修订宪法。含：版本号+文件头 Sync Impact Report、使命与价值优先级、决策原则、协作红线、流程约束、经验升级区、Governance 修订规则（版本语义化：MAJOR 红线语义变化 / MINOR 新增扩展 / PATCH 措辞澄清）。修订只追加记录，不改历史。落盘后停止
- **task.clarify**：先分析展示再提问，最多 2 轮（每轮 ≤6 问，缺什么问什么，禁止拿猜测当澄清）→ 一段话复述请用户确认（闸门）→ 落盘 01-task.md。落盘后停止
- **task.plan**：基于 01 做分析展示与权衡讨论（MECE 议题树 3-5 子议题 → 影响×难度×见效速度打分排序，80% 精力压前 20% → 可证伪 Day-1 假设 → 行动计划留 ≥15% 缓冲）；不产正式 A/B/C 方案（那是 review 的事）；调研证据落 06-research.md（按需）→ 落盘 02。落盘后停止
- **task.review**：压缩为 SCQA 汇报稿（结论前置 30 秒）+ 方案 A/B/C 选择题（含推荐、理由、风险、预案）→ 三拍板（方向/资源/风险预案）→ 会议结论记录拍板/否决/待定/下一步 owner+deadline → 落盘 03。禁止抛问答题。落盘后停止
- **task.check**：宪法合规 + 产物一致性校验（01-task 目标 vs 02 计划 vs 03 拍板 vs 04 进度，06-research 存在时纳入），输出 pass/fail 清单并落盘 checklists/<校验类型>.md
- **task.track**：五段式周志（已完成/进行中/待解决/下一步/需要支持）追加到 04，附契约校验（能否追溯到 02/03？假设是否被推翻？有无黄灯/红灯？）。完成后停止
- **task.aar**：四问复盘（原计划/实际发生/为什么有差异/下次怎么办）→ 规则必须是"下次遇到 X 就做 Y"形式；项目级规则晋升进宪法（带来源任务+修订记录）→ 落盘 05。落盘后停止
- **task.done**：确认 05 完成 → PROJECT.md 状态改已完成 → 主动询问下一个任务（询问不等于执行 task.new）
- **task.list / task.show**：列任务（编号/名称/阶段/状态，读 PROJECT.md）/ 展示状态卡（渲染 00-STATE 并核对 stages_done 各产物真实存在，不一致标 ⚠️）

## 硬规则
1. 宪法未立时，task.new 先提示 task.constitution（用户明确跳过除外）；每份产物落盘前自查宪法，冲突点写进文件
2. 阶段一（澄清）与阶段三（确认）是对齐闸门，未确认不得进入重执行
3. **阶段硬停止**：每条阶段命令完成自身产物与闸门后停止，输出阶段完成报告（①产物清单 ②当前阶段与状态 ③下一建议命令+所需输入）；用户未授权禁止自动调用下一阶段命令
4. **连跑授权**：说"接下来连着跑"=授权推进 1 个阶段（"连跑 N 个阶段"=N）；闸门处必停，闸门 approve（含闸门处"继续"）不消耗授权；不提供无上限连跑；授权存于 00-STATE 跨会话持久
5. 执行中假设被推翻/方向变更 → 立即停，按回溯边表回 task.review（方向性推翻回 task.clarify），到达目标阶段即停；禁止沉没成本硬推
6. 每份产物末尾附检查行 + "宪法校验：□ 符合（冲突点：____）"
7. 裁剪按返工成本：日常事务型 30 秒过五要素不落盘；临时协调型只落盘 01；专项任务型全五段；突发问题型 5 分钟澄清+口头确认+事后 AAR

## 模板结构（内联版，文件版见 core/templates/）
- **00**：frontmatter（task/slug/stage/stages_done/next/chain_grants/suspended_reason/updated）+ 状态卡四栏（当前状态/关键结论/下一步/授权余量）+ 闸门记录
- **01**：任务名称/编号/提出人日期 + 五要素（问题/背景/目标/范围/干系人）+ 时间资源 + 决策人风格 + 用户视角场景 + 澄清记录（≤2 轮）+ 复述确认
- **02**：议题树 + 打分表 + 假设清单（假设/验证方式/推翻后怎么办）+ 行动计划（任务/Owner/截止/产出证据/依赖/缓冲）+ 分析记录/沟通过程
- **03**：SCQA 开场 + 议题摘要 + 方案选择题表 + 风险与预案 + 会议结论 + 分析记录/沟通过程
- **04**：周次 + 五段式 + 契约校验三问
- **05**：四问 + 规则沉淀 + 模板更新动作
- **06**：调研议题（Decision/Rationale/Alternatives considered/证据来源），按需创建
- **宪法**：使命优先级 / 决策原则 / 红线 / 流程约束 / 经验升级区 / 修订记录
